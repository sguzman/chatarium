# Nix packaging — Phase A (candidate)

This is the initial Linux x86_64 slice of the [agentic workstation roadmap](AGENTIC_WORKSTATION_ROADMAP.md). The existing Windows and Cargo development paths are unchanged.

## Build contract

- Nixpkgs, rust-overlay and crate2nix source revisions are pinned explicitly in the flake. The toolchain comes from rust-toolchain.toml (currently Rust 1.98.1).
- crate2nix generates the workspace graph from Cargo.lock with that Cargo toolchain. Import-from-derivation is deliberate; Rust crates must be independently cached rather than using an all-dependencies Cargo build.
- The initial output is named desktop-unwrapped, not default: it is a compilation acceptance target, not a packaged runnable desktop.
- The lockfile is generated by Nix itself and committed from the actual [CI artifact](https://github.com/sguzman/chatarium/actions/runs/45288932942), after lock generation and pinned toolchain verification passed.
- Local development uses the pinned toolchain and Linux GUI libraries. Existing host Secret Service and graphics drivers remain host responsibilities. No system packages are installed automatically.

## Authentication sidecar packaging plan

The current Rust bridge finds its bootstrap and bridge scripts relative to CARGO_MANIFEST_DIR. Its normal launch can invoke Git and the pinned upstream package-manager bootstrap. Neither is acceptable in an immutable installed Nix package.

The candidate siwc-sidecar package pins the same DevKit revision as the existing submodule and extracts only the build/runtime tarballs selected from its upstream package-lock, using each original integrity hash. It builds TypeScript inside Nix and retains only production modules, built SDK, bridge scripts and notices. It does not yet change the Rust launch path. The additional flake input requires a fresh CI-generated lockfile. The packaged launch must not run Git or package installation, and must fail closed if its runtime is missing. Existing source-tree development behavior must remain intact. The credential boundary, Secret Service and removal of API-key environment variables remain unchanged.

## Verification

The Nix CI candidate generates a real flake.lock, verifies the toolchain, and builds desktop-unwrapped. It uses the public repository and synthetic build data only, never a private user archive or account.

The first desktop compilation failed in `chatarium-protocol`: crate2nix isolates each crate, but `stability.rs` embeds the canonical workspace-level schema. The first override succeeded in compiling the protocol crate, but the store then failed on its workspace-level fixture include ([second run](https://github.com/sguzman/chatarium/actions/runs/45296926124)). Generalized filtered workspace layouts now cover protocol, store and desktop, without modifying canonical schemas or fixtures. [Failure evidence](https://github.com/sguzman/chatarium/actions/runs/45289303459). Rebuild acceptance is pending.
