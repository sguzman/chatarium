# Chatarium Edge Bridge

This directory contains the **critical-path browser runtime** for Chatarium's read-only interoperability with the user's existing ChatGPT conversation corpus.

It replaces two retired history-discovery approaches:

1. the Tampermonkey account-history bridge;
2. Edge Bridge 0.1/0.2 exact-C01 request reconstruction/replay.

The Flight Recorder elsewhere in `browser/` remains a separate durability/evidence tool.

## Current architecture: 0.3.0 CDP discovery

```text
Chatarium Desktop
    ↕ typed HTTP loopback on 127.0.0.1:43117
Edge MV3 extension service worker
    ↕ bounded chrome.debugger attachment
authenticated chatgpt.com tab
    ↕ Chrome DevTools Protocol Network domain
actual first-party /backend-api/* traffic
```

History discovery no longer assumes that a historical endpoint or query profile will appear.

For one bounded discovery command, the extension:

1. finds one authenticated `https://chatgpt.com/*` tab;
2. attaches `chrome.debugger` to that tab;
3. enables the CDP Network domain;
4. reloads the tab itself;
5. observes the **actual current first-party network responses** generated by ChatGPT;
6. considers only HTTP 200 JSON responses under `/backend-api/` whose path is conversation/sidebar/pin-like;
7. waits for each candidate response to finish;
8. reads its body with `Network.getResponseBody`;
9. enforces bounded response size and JSON traversal;
10. extracts only typed conversation-summary candidates and safe structural metadata;
11. detaches the debugger.

The extension does **not** invent or replay a global conversation-list request during discovery.

## Why 0.1/0.2 were retired

Edge Bridge 0.1.0 proved that the extension transport itself worked:

- desktop roundtrip;
- ChatGPT tab selection;
- MAIN-world execution;
- authenticated session;
- account context;
- HTTP 200;
- Rust parsing.

But its reconstructed ordinary-history request returned an unconfirmed empty result.

A re-audit of the private 2026-10-03 HAR then established that the captured ordinary global `/backend-api/conversations?...limit=20&offset=0` requests were HTTP 429. That HAR established request shape/context, not successful ordinary-history semantics.

Edge Bridge 0.2.0 therefore made the one allowed evidence-driven correction: wait for the exact first-party ordinary-history request, retain its browser-local application context, and replay it.

The final 0.2.0 live validation failed both before and after a full ChatGPT-tab reload with:

```text
tab=yes
account-context=yes
request-context=no
first-party-http=unknown
context-headers=0
first_party_request_context_unavailable
```

That failure established that **waiting for one frozen historical C01 request is itself an unreliable runtime dependency**. Per the human-QA stop rule, the replay architecture was retired instead of receiving another speculative patch.

## Permissions

The 0.3.0 manifest contains:

- `debugger`
- `scripting`
- `storage`
- host access to `https://chatgpt.com/*`
- host access to `http://127.0.0.1:43117/*`

The `debugger` permission is powerful and intentionally explicit. It exists only because history discovery now needs the browser's own DevTools Network stream and response-body access. The implementation attaches only to the selected ChatGPT tab for the bounded discovery interval and detaches in a `finally` path.

Do not add cookies, browsing-history, `<all_urls>`, debugger access to arbitrary tabs, or other broad permissions merely for convenience.

## Credential and private-data boundary

Raw reusable authentication material does not cross into Rust.

During CDP discovery:

- request cookies are not returned to Chatarium;
- `Authorization` values are not returned to Chatarium;
- raw request-header sets are not returned to Chatarium;
- browser storage is not returned to Chatarium;
- `ChatGPT-Account-ID`, when observed, is retained only in `chrome.storage.session` so the already-evidenced exact C02 conversation read can operate later;
- candidate response bodies are reduced in the extension to typed conversation summaries plus safe structural metadata before crossing loopback.

The Rust side receives fields such as:

- candidate backend path;
- query **key names**, not values;
- surface classification;
- observed conversation-summary identities/titles/timestamps;
- cursor counts/type signals;
- truncation state;
- proof counters.

## Supported commands

The loopback wire protocol remains version 1.

Current commands:

- `probe_auth`
- `discover_history_surfaces`
- `fetch_conversation`

`list_conversations` remains only as an explicit retirement response so stale desktop code cannot silently revive exact-C01 replay.

Current profiles:

- authentication probe: `chatgpt-me-v1`
- history-surface discovery: `cdp-history-discovery-v1`
- exact C02 conversation read: `2026-10-03.001`

## Discovery proof ladder

A successful discovery result proves only the boundaries it actually crossed:

- extension version;
- desktop roundtrip;
- exact ChatGPT tab found;
- debugger attached;
- Network domain enabled;
- automatic tab reload started;
- number of network responses observed;
- number of successful `/backend-api/` responses observed;
- number of list-like JSON candidate responses observed;
- response-body read failures;
- oversized bodies rejected;
- malformed JSON rejected;
- candidate surface/item counts;
- browser-local account context when observed.

It does **not** claim that any candidate surface is complete account-wide history.

The desktop therefore renders successful discovery as `PROOF PARTIAL` and explicitly reports `completeness=unproven`.

A candidate surface can be promoted into the true ConversationList baseline only after separate evidence establishes its pagination/completeness semantics.

## Exact conversation reads

The independently evidenced C02 path remains:

```text
GET /backend-api/conversations/<id>?num_turns=10&include_has_versions=true
```

After discovery has safely observed browser-local account context, the extension can execute this exact read in the ChatGPT tab's MAIN world. Rust still requires exact remote-identity validation before a durable mirror is committed.

No same-thread mutation support is inferred from this read path.

## Loopback

The service worker talks only to `127.0.0.1:43117` and sends `X-Chatarium-Bridge: edge-mv3-v1`.

Chatarium independently:

- binds loopback only;
- rejects ordinary web origins/preflight;
- accepts the Chromium extension-origin shape;
- enforces request-size limits;
- correlates command/result IDs;
- rejects the retired userscript bridge marker.

Native Messaging is not used.

## Human QA gate

Do not hand this extension to the operator merely because its files exist.

Before each live browser validation:

- browser runtime syntax/invariant tests must pass;
- the pure CDP history classifier tests must pass;
- Rust format/check/tests must pass;
- Linux desktop check/tests must pass;
- the current issue must document exactly what the run can prove.

The extension performs the ChatGPT-tab reload itself during discovery. The operator must not be asked to manually reload repeatedly, open DevTools, inspect network traffic, or collect another HAR merely to exercise 0.3.0.

Follow `docs/HUMAN_QA.md` and issue #103.

## Automated package check

```sh
node --check browser/edge-bridge/service-worker.js
node browser/edge-bridge/check.mjs
```

The package check freezes the 0.3 permission surface and exercises the pure history classifier against ordinary, rate-limited, unrelated-JSON, nested-sidebar, cursor, and repeated-observation cases.
